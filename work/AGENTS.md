# Work Profile Rules

## Scope and Access

- Follow the shared `AGENTS.md` security rules.
- Use work accounts and credentials only for an authorized work objective.
- Use the configured work-access integration where available. Personal access
  must be explicitly requested; do not mix work and personal credentials.
- Keep company-specific hostnames, account details, workspace paths, and
  credentials in the private configuration repository or local environment.

## Workspace and Git

- Before cloning, search the configured project root for an existing checkout.
- Use the repository's verified corporate Git identity for work commits.
  Use the appropriate personal identity only in confirmed personal projects.
- Run `git fetch` before starting a task in a Git repository, as required by
  the shared rules; never pull or rewrite branches without authorization.

## Human-Facing Work Communications

- Keep tickets, pull requests, review comments, and release notes concise.
- Describe confirmed changes and impact; exclude agent workflow and raw logs.
- Follow the repository's contributor guidelines and review policy.
- Publish external updates only when explicitly or previously authorized.
